# Run these four files in Supabase

Four copy-pastes, in order. Nothing to install, nothing to download.

## Where to go

1. Open **supabase.com/dashboard** and sign in.
2. Click your project, **healthpulse**.
3. In the **far-left icon sidebar**, click the **SQL Editor** icon. It looks like a
   small terminal window, `>_`. Hovering over it says "SQL Editor".
4. Click **+ New query** at the top of the panel that opens.

You now have a big empty text box with a **Run** button at the bottom right.

## What to run, in this order

| Order | File | What it does |
|---|---|---|
| 1st | `1_schema.sql` | Creates the 34 tables |
| 2nd | `2_security.sql` | Turns on the rules that keep each person's health data private |
| 3rd | `3_reference_data.sql` | Loads biomarkers, lab-name synonyms, reference ranges, nutrient targets, foods |
| 4th | `4_check_it_worked.sql` | Changes nothing. Tells you whether the first three worked |

For each one:

1. Open the file on GitHub and click the **copy** button (the two-squares icon at
   the top right of the code view). That copies the whole file.
2. Go back to the SQL Editor, click in the text box, select everything already
   there (Ctrl+A) and paste over it (Ctrl+V).
3. Click **Run**, or press **Ctrl+Enter**.
4. Wait for it to finish. Parts 1 and 2 take a second or two. Part 3 takes longer
   because it is loading a few thousand rows.
5. Click **+ New query** again and do the next file.

## How you know it worked

After the fourth file, you get a table of results. **Every row should say PASS.**

If a row says `CHECK`, it names which part to run again. Running any part a second
time is safe: nothing is duplicated and nothing is lost.

## If something goes red

Supabase shows errors under the text box in red.

- **"relation ... does not exist"** — a part was run out of order. Start again from
  Part 1.
- **"permission denied for schema auth"** — you are signed in to the wrong project,
  or pasted only part of a file. Copy the whole file.
- Anything else — copy the red text and send it over. Do not try to fix the SQL by
  hand; these files are generated.

## Do not run

`db/tests/000_local_supabase_shim.sql` is for testing on a plain PostgreSQL server.
It fakes the `auth` and `storage` pieces that Supabase already gives you properly.
Running it on your real project would be pointless at best.

## Where these files come from

They are generated by joining the files in `db/migrations/`, `db/policies/` and
`db/seed/` in order. Those are the sources of truth. Do not edit anything in this
folder by hand.
